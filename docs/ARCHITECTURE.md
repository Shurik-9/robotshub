# Архитектура и воспроизводимый запуск

## Что входит в работающий продукт

- `artifacts/robotshub/src/` — React-приложение с маршрутизацией Wouter, состоянием проекта и расчётами в браузере.
- `artifacts/robotshub/public/` — данные карты, документы кейсов, изображения и другие ресурсы, доступные по URL.
- `artifacts/robotshub/src/data/` — каталог решений и шаблоны объектов. Приложение не запрашивает базу данных для этих данных.
- `Dockerfile` — сборка в Node.js 24 / pnpm 10.26.1 и выпуск статических файлов через nginx.
- `compose.yaml` — один сервис `web`, порт хоста по умолчанию 8080; `deploy/nginx.conf` — SPA fallback и `/healthz`.

Схема: браузер → nginx → HTML/JS/CSS/JSON/изображения. Расчёты и пользовательские параметры обрабатываются в браузере; проект сохраняется в localStorage этого браузера. Учётных записей и общего серверного хранилища в этом маршруте нет.

## Отдельный каркас API

`artifacts/api-server` и `lib/db` есть в исходном монорепозитории, но пользовательский React-интерфейс не использует их для основного маршрута. API публикует только инфраструктурный health endpoint и требует `DATABASE_URL` при запуске. Наличие API в исходниках **не означает**, что он нужен для Docker-демонстрации. Мы намеренно не запускаем PostgreSQL и API как обязательные контейнеры: иначе проверка сайта без базы завершилась бы ошибкой. Если впоследствии добавятся реальные серверные функции, потребуется отдельная конфигурация базы, миграции, резервное копирование и документированные проверки.

## Параметры

| Где | Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| Docker Compose | `WEB_PORT` | `8080` | Порт на компьютере проверяющего |
| Vite (локально) | `PORT` | `5173` | Порт сервера разработки |
| Vite (локально) | `BASE_PATH` | `/` | Префикс URL при специальной сборке |

Docker всегда собирает для `/` и обслуживает приложение на корне сайта. Для размещения под подкаталогом нужна отдельная сборка с согласованными `BASE_PATH` и конфигурацией веб-сервера; текущий Compose поддерживает корень сайта. Никаких обязательных секретов для описанного веб-приложения нет.

## Ограничения доказательности

Карта объединяет исходные отраслевые записи и пересекающиеся тематические подборки; тематические счётчики не прибавляются к общему количеству. Отраслевая принадлежность решения не доказывает применимость к конкретной площадке. Экономика рассчитывается только в пределах модели операции и доступных исходных параметров; отсутствие валидированной модели показывается явно, а не заменяется общим шаблоном.
