# Внешние настройки после аудита RobotsHub

Изменения приложения и настроек домена — разные операции. Этот список не означает, что DNS, кэш или сжатие уже исправлены.

## 1. Подключить www.robotshub.ru

При проверке `robotshub.ru` доступен, а `www.robotshub.ru` не разрешается в DNS.

1. В Publishing → Domains добавить **www.robotshub.ru как отдельный домен**. Подключение корневого домена не создаёт www автоматически.
2. Скопировать именно те A/TXT-записи, которые платформа покажет для www, в DNS-панель регистратора. Не подставлять адрес из примера или старую запись корневого домена.
3. Дождаться подтверждения домена и проверить HTTPS.
4. После подключения настроить HTTP 301/308 с www на основной `https://robotshub.ru`, сохраняя путь и параметры запроса, через поддерживаемый механизм текущего хостинга/прокси. DNS-запись сама по себе HTTP-редирект не выполняет. Возможность и место настройки редиректа нужно подтвердить; переключателя, которого нет в документации, здесь не предполагается.

Проверка:

```sh
curl -I 'https://www.robotshub.ru/cases?test=1'
```

Ожидается редирект на `https://robotshub.ru/cases?test=1`, без цикла и без потери параметров.

Документация: https://docs.replit.com/features/publishing/custom-domains

## 2. Кэширование ресурсов

Настроить заголовки в слое, который действительно отдаёт статические файлы RobotsHub:

- `/assets/*` с хэшированными именами: `Cache-Control: public, max-age=31536000, immutable`.
- HTML-оболочки, включая `/_seo/*.html` и SPA fallback: `Cache-Control: no-cache, max-age=0, must-revalidate`.
- Не применять годовой immutable-кэш к `logo.jpg`, sitemap, каталожным JSON и другим файлам с неизменяемым именем.

Официальная документация статической публикации описывает custom response headers, но её пример для одиночного приложения через `.replit` нельзя автоматически переносить в этот monorepo: сервисы здесь принадлежат артефактам. Перед изменением нужно подтвердить поддерживаемую схему заголовков для текущего artifact static service либо настроить их на проверенном внешнем прокси.

Документация: https://docs.replit.com/features/deployment-customization/static-deployments-advanced

## 3. Сжатие

Контрольный GET главного JS публичной сборки с `Accept-Encoding: br, gzip` вернул 1 892 713 байт без `Content-Encoding`. Это подтверждено согласованным GET-запросом, а не только HEAD.

Проверить **GET** реального JS/CSS с `Accept-Encoding: br, gzip`, а не только размер локального gzip-файла или HEAD без согласования кодирования:

```sh
curl -sS -D - -H 'Accept-Encoding: br, gzip' \
  'https://robotshub.ru/assets/ИМЯ-ИЗ-ТЕКУЩЕГО-HTML.js' -o /dev/null
```

Ожидается `Content-Encoding: br` либо `gzip` и корректное разделение вариантов ответа (`Vary: Accept-Encoding` или эквивалентная обработка платформой). Replit указывает, что сжатие управляется платформой; `Content-Encoding` и `Content-Length` зарезервированы. Нельзя просто дописать `Content-Encoding: gzip` к несжатым байтам — сайт перестанет открываться.

Если согласованный GET также не сжат, передать в поддержку/настройки обслуживающего слоя конкретный URL и заголовки. Строка `Server: Google Frontend` сама по себе не доказывает, что пользователь управляет App Engine и может менять его конфигурацию.

## 4. Скрипт i.replit.com/script.js

Скрипт есть в опубликованном HTML, но отсутствует в исходном `artifacts/robotshub/index.html`. Удаление строки из исходников не устранит инжекцию.

1. Сравнить HTML из готовой локальной сборки с опубликованным.
2. Выяснить, какой слой публикации добавляет скрипт.
3. Отключать через подтверждённую настройку этого слоя, если она доступна, либо уточнить поддерживаемый способ у платформы. Документированный переключатель отключения при проверке не найден.
4. Повторно проверить опубликованный HTML. Не блокировать скрипт вслепую общей CSP: это отдельная настройка, способная затронуть Метрику, шрифты и API.

## Что проверять после следующей публикации приложения

- `/`, `/solutions`, `/vendors` и отдельный `/cases/<id>` отдают свои title/description/canonical/OG **в исходном HTML**.
- Новые точные SEO rewrites находятся перед SPA wildcard, а `/glossary` продолжает открывать самостоятельную статью.
- Неизвестный маршрут показывает 404 и получает `meta robots=noindex` после рендера SPA. **HTTP 404 этим этапом не реализован:** fallback статического хостинга всё ещё может отвечать 200.
- `/lead` открывается до, во время и после публикации. Один прежний временный 404 не устанавливает его причину.
- `lastmod` в sitemap не придуман: даты страниц нужно добавлять только при наличии достоверной даты содержательного изменения.
