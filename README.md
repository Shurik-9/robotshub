# «Железный аргумент» — Центр подбора роботизации

Веб-приложение для изучения отраслевой карты робототехники, описания площадки, сравнения решений и предварительной оценки внедрения. Интерфейс на русском языке.

## Живая версия

Откройте [robotshub.ru](https://robotshub.ru/) без установки. Для воспроизводимой проверки исходного кода используйте локальный запуск ниже. Новые изменения в рабочей копии могут появиться на публичном сайте только после следующей публикации.

## Запуск для проверяющего: Docker Compose

Понадобятся Docker с Compose v2, доступ к Docker Hub и npm при первой сборке, свободный порт 8080 и рекомендуемые 4 ГБ оперативной памяти для сборки. Репозиторий открыт: для клонирования аккаунт GitHub не требуется.

```bash
git clone https://github.com/Shurik-9/robotshub.git
cd robotshub
docker compose up --build --wait
```

Откройте **http://localhost:8080**. Проверка работоспособности:

```bash
curl -f http://localhost:8080/healthz
curl -f http://localhost:8080/map/map-data.json
curl -f 'http://localhost:8080/quick-select?sector=sector-medicine'
```

Последняя команда проверяет, что сервер отдаёт страницу и для внутренних маршрутов приложения. Открывать её для интерактивной проверки нужно в браузере. Сборка идёт для `linux/amd64`; на ARM/Mac с Apple Silicon Docker использует эмуляцию и первая сборка может быть медленнее. nginx обслуживает статический сайт и передаёт `/news`, `/news/sitemap.xml`, `/news/:id`, `/api/news` и `/admin-news` отдельному движку новостей. Полный API-сервер и PostgreSQL не нужны. SQLite новостей хранится в постоянном томе `news-data`; при первом запуске лента пустая.

Если 8080 занят, создайте `.env` из `.env.example` и измените `WEB_PORT` (например, на 18080). После изменения порта используйте `http://localhost:<WEB_PORT>`. Переменная не содержит секретов.

Остановить: `docker compose down` (том новостей сохраняется; `down -v` удалит его вместе с данными). Логи: `docker compose logs --tail=100 web news`. Состояние: `docker compose ps`. При сбое сборки: проверьте доступ к Docker Hub/npm и повторите `docker compose build --no-cache`. Если `/healthz` отвечает, а внутренняя страница не открывается, проверьте `docker compose logs web news`; конфигурация веб-сервера находится в `deploy/nginx.conf`. Модерация новостей доступна только при переданном через окружение необязательном `ADMIN_TOKEN`; без него административные запросы отклоняются.

## Что проверить в браузере

1. На главной странице выберите отрасль на карте и нажмите переход к описанию объекта.
2. На «Быстром выборе» изучите отраслевые доказательства и выберите один из трёх типовых объектов или «Свой объект».
3. Сохраните параметры объекта и изучите отфильтрованный каталог.
4. Для поддерживаемого сценария посмотрите предварительную экономику; для неподдерживаемого — явное объяснение ограничения вместо фиктивных чисел.
5. **Симуляция.** После выбора подходящего решения перейдите из расчёта в «Симуляцию»: роботы выполняют задания на схеме вашей площадки с проездами, этажами и лифтом. Если расчётного проекта нет, страница предложит отдельное безопасное демо-склада. Это схема работы техники, а не прогноз окупаемости; демо не изменяет сохранённые параметры объекта.
6. Откройте отчёт, затем обновите страницу: данные вашего проекта сохраняются **только в локальном хранилище этого браузера**. При очистке данных сайта или переходе на другое устройство они не переносятся.

Подробнее: [маршрут проверки](docs/REVIEWER_GUIDE.md), [статус функций](docs/STATUS.md) и [команды проверки](docs/VALIDATION.md).

## Изменения комплекта

Текущий состав и ограничения описаны в [STATUS.md](docs/STATUS.md), изменения относительно предыдущей передачи — в [CHANGELOG.md](docs/CHANGELOG.md). Техническое описание симуляции: [simulation-internals.md](docs/simulation-internals.md).

Дополнительно к новостям nginx передаёт в автономный сервер `/cabinet`, `/lead`, `/api/cabinet` и `/api/leads`. Ссылка «Вендорам» скрыта из публичной навигации, но кабинеты не удалены. Для создания администратора передайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` через окружение; для модерации новостей нужен `ADMIN_TOKEN`. Не коммитьте значения в репозиторий. Без этих параметров публичный сайт работает, административный доступ не создаётся.

В томе `news-data` сохраняются SQLite и рабочая копия каталога кабинета. Исходный каталог копируется туда только при первом запуске. Одобрение правок в кабинете **не пересобирает статический каталог сайта**: для его обновления требуется отдельное согласованное обновление исходного JSON и новая сборка. Данные с robotshub.ru в этот комплект не включены.

## Запуск разработчика без Docker

Официально воспроизводимый сценарий выше — Docker. Для разработки на Linux x86‑64 нужны Node.js 24 и pnpm 10.26.1:

```bash
pnpm install --frozen-lockfile
pnpm --filter @workspace/robotshub run dev
```

Откройте http://localhost:5173. `PORT` и `BASE_PATH` необязательны (по умолчанию 5173 и `/`). Для сборки: `pnpm --filter @workspace/robotshub run build`. Текущий lockfile ограничивает нативные зависимости архитектурой x86‑64: на других архитектурах используйте Docker Compose.

## Устройство и ограничения

Основной интерфейс — React/Vite в `artifacts/robotshub`, данные карты и каталога входят в репозиторий. Симуляция работает на собственном движке Canvas 2D (автомат состояний, маршруты A* по проездам, лифт и зарядка) без внешних сервисов. Docker собирает сайт и раздаёт `dist/public` через nginx; внутренние URL приложения перенаправляются на `index.html`, а новости обслуживает отдельный SQLite-движок из `artifacts/api-server/src/news-engine`. Полный API и `lib/db` с PostgreSQL для этого запуска **не нужны**. Подробности — в [архитектуре](docs/ARCHITECTURE.md).

ТЭО — предварительная модель с ограничениями области применимости, а не финансовая гарантия.
