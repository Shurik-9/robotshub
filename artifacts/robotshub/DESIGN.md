# DESIGN.md — дизайн-система платформы

Единый источник визуальных правил. Любой экран, компонент или графика делается
только по этому документу. Если решение не описано здесь — спроси, не выдумывай.

---

## 1. Принципы (проверять каждое решение по ним)

1. **«Диспетчерский терминал», а не «лендинг».** Платформа — рабочий инструмент
   для инженера и финансового директора. Плотность данных высокая, декор — ноль.
2. **Данные главнее декора.** Каждая цифра имеет источник; интерфейс подсвечивает
   происхождение данных, а не «красивость». Никаких декоративных градиентов,
   теней-блюров и иллюстраций-заглушек.
3. **Нейтральность = дизайн.** Ранжирование и порядок карточек не зависят от
   коммерции; рекламные блоки всегда визуально отделены (см. §6.2).
4. **Цифры — главный герой.** Все метрики — моноширинным шрифтом с табличными
   цифрами; они крупнее и контрастнее подписей.
5. **Тёмная тема — основная.** Продукт существует в одном экземпляре темы:
   тёмный «терминал». Светлая поверхность допустима только в отчётах PDF.

## 2. Палитра

### 2.1. Базовые поверхности

| Токен | HEX | Где используется |
|---|---|---|
| `bg` | `#0B1220` | Фон страницы, фон canvas-сцены |
| `surface` | `#111A2E` | Карточки, панели, модальные окна |
| `surface-2` | `#17223A` | Вложенные блоки, шапки таблиц |
| `border` | `#1E293B` | Основные границы, разделители |
| `border-strong` | `#334155` | Активные границы, обводка зон, hover |

### 2.2. Текст

| Токен | HEX | Использование |
|---|---|---|
| `text-primary` | `#E2E8F0` | Заголовки, основной текст |
| `text-secondary` | `#94A3B8` | Подписи, единицы измерения, примечания |
| `text-muted` | `#64748B` | Служебные подписи, ленты событий, счётчики «найдено» |
| `text-disabled` | `#475569` | Недоступные элементы |

### 2.3. Акценты и семантика

| Токен | HEX | Использование |
|---|---|---|
| `accent` | `#22D3EE` (cyan) | Главный акцент: активные состояния, ссылки, фокус, свечение роботов, «операции» |
| `accent-soft` | `rgba(34,211,238,0.08)` | Подложки выбранных элементов |
| `money` | `#FACC15` (amber) | Деньги: экономия, OPEX/CAPEX-суммы, зарядные станции |
| `success` | `#34D399` | Положительный эффект, «решение применимо» |
| `warning` | `#FB923C` | Вне диапазона (soft), интерпретация «3–5 лет» |
| `danger` | `#F87171` | Ошибки, «не применимо», низкий заряд батареи, окупаемость > 5 лет |

### 2.4. Правила цвета

- Акцентный cyan **никогда** не используется как фон текста — только текст,
  границы, иконки, тонкие подложки.
- `money` (#FACC15) зарезервирован за деньгами. Не красить им кнопки и ссылки.
- Запрещённые цвета: чистые `#00FF00`/`#FF0000`/`#0000FF`, фиолетовые и синие
  градиенты (`from-purple-500 to-pink-500` и любые производные), любые цвета
  вне этого документа.
- Градиенты запрещены везде, кроме свечения спрайтов в canvas-сцене.

**Tailwind-соответствие** (использовать эти классы):

```js
// tailwind.config.ts — extend
colors: {
  bg: "#0B1220", surface: "#111A2E", surface2: "#17223A",
  line: "#1E293B", "line-strong": "#334155",
  ink: "#E2E8F0", ink2: "#94A3B8", ink3: "#64748B",
  accent: "#22D3EE", money: "#FACC15",
  ok: "#34D399", warn: "#FB923C", bad: "#F87171",
}
// шрифты
fontFamily: {
  sans: ["Inter", "system-ui", "sans-serif"],
  mono: ["JetBrains Mono", "ui-monospace", "monospace"],
}
```

## 3. Типографика

| Стиль | Шрифт | Размер | Начертание | Примечание |
|---|---|---|---|---|
| H1 страницы | Inter | 22–24px | 600 | Один на страницу |
| H2 секции | Inter | 16–18px | 600 | |
| H3 / карточка | Inter | 13–14px | 600 | |
| Тело | Inter | 13–14px | 400 | line-height 1.5 |
| Подпись/примечание | Inter | 11–12px | 400 | `ink2` |
| **Метрика** | JetBrains Mono | 20–28px | 500 | `tabular-nums`, всегда mono |
| Метрика в таблице | JetBrains Mono | 13px | 500 | `tabular-nums` |
| Canvas-подписи зон | ui-monospace | 11px | 600 | UPPERCASE, letter-spacing 2px |

Правила:
- Все числа, единицы, цены, проценты, часы — **только моноширинным** (`font-mono tabular-nums`).
  Исключений нет: это главный носитель «инструментальности».
- Заголовки — без CAPS; CAPS только для микро-подписей (над KPI, зоны на схеме).
- Единицы измерения — отдельным элементом меньшего кегля (`ink2`), не внутри числа.
- Многострочные описания — не шире ~70 символов в строке.

## 4. Сетка, отступы, формы

- База отступов: **4px**. Используемые шаги: 4/8/12/16/24/32/48.
- Контентная колонка: max-width **1280px**, боковые поля 24–32px.
- Скругления: карточки и панели **12px**, кнопки и поля **8px**, бейджи — pill.
- Тени не используем. Разделение слоёв — границами `border` и разницей
  поверхностей (`bg` → `surface` → `surface-2`).
- Сетка страницы: слева навигация/степпер (240–280px), справа контент.
  На шаге расчёта: форма слева (~55%), живые результаты справа (~45%), sticky.

## 5. Компоненты

### 5.1. Карточка решения (ключевой компонент)

Анатомия сверху вниз:
1. Строка 1: **название** (H3) + бейдж типа (AMR/FMR/…) + коммерческие бейджи (§6.2);
2. Строка 2: вендор · регион · статус (Эксплуатация/Пилот/НИОКР — цвет точки:
   ok/warn/ink3) · УГТ `8/9`;
3. ТТХ: 3–4 ключевых параметра в `font-mono` (грузоподъёмность, скорость,
   производительность) с единицами в `ink2`;
4. **Цена** — mono, крупно, `#E2E8F0`, подпись «с НДС, без доставки и ПНР» в `ink3`;
5. Кейс внедрения (если есть) — 2 строки максимум, с числами, выделенными mono;
6. Подвал: источник данных (иконка `IconSourceDoc` + текст `ink3`) и кнопки:
   «Сравнить» (secondary) + «Рассчитать» (primary).

Размер: ширина в сетке каталога 3 колонки (min 360px), hover — `border-strong`.

### 5.2. Кнопки

| Тип | Вид |
|---|---|
| Primary | фон `accent`, текст `#0B1220`, скругление 8px, font 13px/600 |
| Secondary | прозрачный фон, граница `border-strong`, текст `ink` |
| Ghost | без фона и границы, текст `ink2`, hover → `ink` |
| Опасная | граница/текст `bad`, только для необратимых действий |

Hover — смена границы/фона на 10% светлее. Активная — 10% темнее. Фокус —
`outline 2px accent` со смещением 2px.

### 5.3. Поля ввода и валидация

- Поле: фон `surface-2`, граница `border`, фокус — граница `accent`.
- Формат: подпись сверху (12px `ink2`), значение mono, единица справа в поле.
- **Значение вне диапазона min/max**: граница `warning`, под полем подсказка
  «Диапазон: 10 000–100 000 м²» — ввод НЕ блокируется, помечается в отчёте.
- Ошибка (текст/число невалидны): граница `bad` + конкретное сообщение.
- Под каждым полем — примечание-источник из шаблона (`note`), 11px `ink3`.

### 5.4. KPI-панель / счётчики

- Подпись: 10–11px UPPERCASE `ink3`, letter-spacing 1.5px;
- Значение: mono 24–28px, `tabular-nums`; цвет по смыслу: операции — `accent`,
  деньги — `money`, нейтральные — `ink`;
- Тикающие счётчики (симуляция) — обновление не чаще 4 раз/сек, без анимации отскока.

### 5.5. Степпер мастера

Горизонтальный, 4 шага: иконки из `brand-icons` (IconSelect, IconCompare,
IconCalculator, IconVisualization) + подписи. Пройденный — `accent`, текущий —
`accent` с подложкой `accent-soft`, будущий — `ink3` с границей `border`.
Клик по пройденному шагу возвращает назад.

### 5.6. Таблицы (сравнение решений, сценарии)

- Шапка: `surface-2`, 11px UPPERCASE `ink2`;
- Числа — mono; лучший показатель в строке — `accent` + маленький ▲;
- Худший — не красить, только нейтрально; красный — только для «не применимо»;
- Строка hover — `surface`;
- Первый столбец закреплён (sticky).

### 5.7. Графики (экономика)

- Оси и сетка — `border`; подписи — 11px `ink2`;
- Линии/столбцы: базовый сценарий — `ink3` (пунктир), роботизация — `accent`,
  RaaS/лизинг — `money`;
- Точка окупаемости — вертикаль `money` пунктиром + подпись mono «28 мес»;
- Подписи значений — всегда mono. Столбцы без скруглений и теней.

### 5.8. Пустые состояния

Шаблон: иконка из brand-icons (не эмодзи) 32px `ink3` → заголовок 14px/600 →
объяснение 13px `ink2` → действие-кнопка. Обязательный текст «почему пусто»:
напр., «Нет решений под этот объект: ширина прохода 1,5 м уже допустимого для
выбранных типов. Ослабьте ограничение или добавьте решений вручную».

### 5.9. Тултипы источников (механика доверия)

Любая расчётная цифра — с иконкой `IconSourceDoc` (источник) или
`IconInfoAssumption` (допущение). Hover: фон `surface-2`, граница `border`,
max-width 320px: значение → формула одной строкой → источник («Каталог ФЦ БАС,
2026» / «Допущение методики: интеграция 20–50% от техники»).

## 6. Правила нейтральности в UI (не нарушать)

### 6.1. Ранжирование
Порядок решений определяется только соответствием объекту (ТТХ/ограничения),
затем УГТ, затем ценой. Коммерческие поля на порядок не влияют — в коде выдачи
коммерческие атрибуты физически не участвуют в сортировке.

### 6.2. Коммерческие бейджи

| Бейдж | Вид | Место |
|---|---|---|
| «Партнёр» | граница `accent`, текст `accent`, фон `accent-soft` | только в карточке, шапка карточки |
| «Реклама» | граница `money`, текст `money` + маркировка рекламы (erid) | только отдельный блок «Продвижение», НЕ в общей сетке |
| «Собственный бренд» | граница `ink2`, текст `ink` | как обычная карточка в общей сетке, бейдж обязателен |

Рекламный блок: отделён рамкой `money` 1px, заголовок блока «Продвижение»,
стоит после органической выдачи. Никогда — в первых позициях сетки.

### 6.3. Дисклеймеры
Внизу расчёта и в отчёте: «Предварительная оценка. Требует верификации
обследованием объекта. Цены каталога: с НДС, без доставки и пусконаладки».
Стиль: 12px `ink3`, без рамок.

## 7. Иконки и техника

### 7.1. Иконки интерфейса (brand-icons.tsx)
- Только набор проекта (`src/components/brand-icons.tsx`). lucide-react и
  собственные SVG в UI **не подключать**.
- Правила набора: сетка 24×24, stroke 1.75, round caps/joins, только контур,
  цвет — `currentColor`.
- Размеры в UI: 16px (в строках), 18–20px (кнопки, меню), 24px (пустые состояния ×2).
- Цвет: `ink2` по умолчанию, `accent` для активных, `money` для экономики.

### 7.2. Спрайты техники (симуляция)
- Только файлы `public/assets/tech/png/` + габариты из `registry.json`.
  Рисовать роботов фигурами canvas запрещено.
- Нос техники вправо (angle 0 → +X), поворот `translate → rotate → drawImage`.
- Свечение: `shadowColor #22D3EE, blur 10`; шлейф — 12 затухающих точек cyan.
- Стационарные установки (`props`) не анимируются и рисуются под роботами.

### 7.3. Стиль canvas-сцены
- Фон `bg` + сетка 40px `#141D31`;
- Зоны: заливка `rgba(34,211,238,0.05)`, обводка `#334155` 1.5px, радиус 8px,
  подпись UPPERCASE mono 11px `#94A3B8` по центру;
- Маршруты: пунктир 5/7 `#2A3A55`;
- Зарядные станции: квадрат 24px `money` + ⚡;
- KPI-панель справа: подписи UPPERCASE 10px `ink3`, значения mono, контролы —
  ghost-кнопки с границей `border-strong`;
- Лента событий: mono 11px `ink2`, новые сверху, fade-in.

## 8. Тон текстов

- Профессионально, коротко, без восклицаний и «мы рады сообщить».
- Термины точно: «срок окупаемости», а не «быстрая отдача»; «CAPEX/OPEX»
  допустимы, при первом использовании — расшифровка.
- Числа — в формате ru-RU (пробел-разделитель тысяч, запятая в дробях).
- Кнопки — глаголы: «Рассчитать», «Сравнить», «Экспортировать отчёт».
- Ошибки — конкретные и с действием: не «Ошибка», а «Значение вне диапазона
  10 000–100 000 м². Введите значение из диапазона или подтвердите отклонение».

## 9. Доступность

- Контраст текста к фону: `ink` ≥ 12:1, `ink2` ≥ 5:1, `ink3` ≥ 3.5:1
  (только для второстепенного);
- Клик-зоны ≥ 32×32px, фокус-рамки всегда видимы;
- Информацию не передавать только цветом: статус — точка + текст,
  «лучший в строке» — цвет + ▲.

## 10. Антипаттерны (мгновенный реджект ревью)

1. Фиолетово-розовые градиенты, «космические» фоны, glassmorphism;
2. Эмодзи вместо иконок; иконки-стоки вне набора;
3. Захардкоженные числа в UI вне mono; цифры сансом;
4. Тени вместо границ; скругления 20px+;
5. Реклама в общей выдаче; отсутствие бейджей коммерции;
6. Блокировка ввода при out-of-range вместо предупреждения;
7. Пустые состояния без объяснения причины;
8. Роботы-квадратики в симуляции.

## 11. Как применять (для Replit Agent)

```
Дизайн платформы строго по DESIGN.md в корне проекта. Палитра, типографика,
компоненты, бейджи и запреты описаны там. Перед генерацией любого экрана
перечитай §2–§6 и §10. Иконки — только из src/components/brand-icons.tsx.
Числа — только font-mono tabular-nums. Не подключай сторонние UI-киты поверх
указанных правил, не используй эмодзи и градиенты.
```

Для дизайнера: этот документ + `icons/svg/` (правила §7.1) + `assets/tech/`
(§7.2–7.3) — полный набор для макетов в Figma. Начните с карточки решения (§5.1),
экрана расчёта (§4) и панели симуляции (§7.3) — это три ключевых экрана.
